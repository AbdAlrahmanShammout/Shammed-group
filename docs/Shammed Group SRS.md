# **1. Project Overview**

## **1.1 Purpose**

The purpose of this project is to design and develop a professional
corporate website for **Shammed Group**, a pharmaceutical and healthcare
company established in 2005.

The website should present Shammed Group as a professional company
operating in pharmaceuticals, healthcare, distribution, medical
products, and commercial partnerships.

The website must have a modern, premium, trustworthy, and professional
visual identity suitable for a pharmaceutical and healthcare
organization and aligned with modern European corporate website
standards.

In addition to the public website, the system will include a lightweight
**Admin Dashboard** that allows authorized company personnel to manage
the website\'s content without requiring developer intervention.

# **2. Project Objectives**

The system must achieve the following objectives:

1.  Present Shammed Group professionally to customers, partners,
    healthcare organizations, and potential business partners.

2.  Clearly communicate the company\'s history, capabilities, services,
    and market presence.

3.  Showcase international partners.

4.  Showcase pharmaceutical, medical, healthcare, and nutritional
    products.

5.  Present the company\'s services.

6.  Provide clear contact and location information.

7.  Provide an easy-to-use content management interface.

8.  Allow company administrators to update website content
    independently.

9.  Provide responsive support for desktop, tablet, and mobile devices.

10. Provide a scalable structure that allows additional products,
    partners, services, and content to be added in the future.

## **15.1 Category Management**

Administrators must be able to:

- Create category

- Edit category

- Delete category

- Change category name

- Change category description if implemented

- Reorder categories

- Show/hide category if required

### **Category deletion rule**

A category that contains products must not be deleted directly.

Before deletion, the administrator must be required to move its products
to another category.

The system must provide a replacement category selection.

Example:

> \"This category contains products. Please select another category
> before deleting it.\"

The system must prevent deletion if there is no alternative category
available.

If the category is the only existing category, it must not be deleted if
products are assigned to it.

If a category has no products, it may be deleted directly.

# **37. Security Requirements**

The system must:

1.  Protect Admin Dashboard routes.

2.  Prevent unauthenticated users from accessing admin functionality.

3.  Keep admin credentials out of frontend source code.

4.  Store sensitive configuration in environment variables.

5.  Validate uploaded files.

6.  Validate user input.

7.  Prevent unauthorized content modifications.

8.  Protect APIs from basic malicious input.

9.  Avoid exposing sensitive configuration to the browser.

10. Use HTTPS in production.
